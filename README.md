# Refat's Android Full Backup — V1.0.1 (Multi-Device Edition)
![Project Diagram](assets/Demo.jpg)

> **Engine:** `refat_backup_engine.py` &nbsp;|&nbsp; **Tool:** MTKClient (open-source) &nbsp;|&nbsp; **GUI:** Python 3.14 + CustomTkinter

Supports Legacy MT67xx, Dimensity/Helio, and Samsung MTK SoCs. The backend is a standalone engine with hardware mismatch protection, manifest generation, and post-backup file verification.

## What's Included in V1.0.1

- Bundled MTKClient 2.1.4.1 modules and payload data — no separate MTKClient download is required for normal installs
- First-run recovery downloads the official MTKClient archive to the user profile if the bundled client is missing
- `refat_backup_engine.py` provides unified `backup`, `restore`, `scatter`, and `printgpt` subcommands
- Hardware mismatch guard — engine reads `refat_manifest.json` on restore and blocks cross-flash if HW code doesn't match
- Manifest auto-generated after every backup — stores HW code, timestamp, and backup path
- Post-backup file verification — confirms `preloader.bin`, `boot.bin`, `nvram.bin`, `nvdata.bin` exist on disc
- Device class selector (A / B / C) in Settings — BROM connection steps update live in Backup and Restore tabs
- Linux support in Setup tab — udev rule writer for `/etc/udev/rules.d/80-mtk.rules`
- Home tab now shows live ADB device info panel (battery, storage, SD card, network/SIM, Android version, build/ROM, owner)
- Restore tab shows manifest info (HW code, creation date) after folder scan
- Log colorizer catches `CRITICAL`, `BLOCKED`, `MISMATCH`, `MISSING` keywords

## 📦 Building the Windows Executable

> **Requires:** Python 3.14, PyInstaller 6, Inno Setup 6.3+

### Step 1 — Install build dependencies
```bash
pip install pyinstaller Pillow customtkinter
```

### Step 2 — Extract Tcl/Tk libraries (Python 3.14 only)

Python 3.14 ships Tcl/Tk 9.0 as zip archives via a virtual `//zipfs:/` filesystem that PyInstaller cannot bundle automatically. You must extract them manually:

```bash
python -c "
import zipfile, os
base = r'C:\Python314\tcl'
os.makedirs('tcl_extracted/_tcl_data', exist_ok=True)
os.makedirs('tcl_extracted/_tk_data', exist_ok=True)
zipfile.ZipFile(f'{base}/libtcl9.0.4.zip').extractall('tcl_extracted/_tcl_data')
zipfile.ZipFile(f'{base}/libtk9.0.4.zip').extractall('tcl_extracted/_tk_data')
"
```

### Step 3 — Generate the multi-resolution icon
```bash
python build_icon.py
```

### Step 4 — Build the executable
```bash
pyinstaller build.spec
```
Output: `dist/RefatAndroidBackup/RefatAndroidBackup.exe`

The build spec automatically:
- Bundles `customtkinter` theme JSONs via `collect_data_files`
- Bundles `_tcl_data` / `_tk_data` from `tcl_extracted/`
- Bundles `requirements.txt`, the engine, MTKClient Python modules, MTKClient payloads, and configuration data into `_internal/`
- Executes the bundled MTKClient in-process so installed copies do not require a separate Python command
- Copies `python314.dll` to both `dist/RefatAndroidBackup/` and `dist/RefatAndroidBackup/_internal/`

### Step 5 — Build the installer (optional)
```bash
"%ProgramFiles(x86)%\Inno Setup 6\ISCC.exe" installer.iss
```
Output: `installer_output/RefatAndroidBackup_V1.0.1_Setup.exe`

### Automatic GitHub Releases

Push a version tag beginning with `v` to build and publish a Windows Release automatically:

```bash
git tag v1.0.1
git push origin v1.0.1
```

The workflow installs the full requirements, extracts Tcl/Tk, builds the PyInstaller bundle, compiles the Inno Setup installer, creates a portable ZIP, and attaches both files to the GitHub Release. It can also be started manually from the Actions tab with `workflow_dispatch`.

## ⚠️ Known Build Issues & Fixes

### python314.dll — "Failed to load Python DLL"
PyInstaller 6 places the DLL inside `_internal/` but the bootloader also needs it next to the `.exe`. The `build.spec` post-build step handles this automatically. If you see this error after a manual build, run:
```bash
copy C:\Python314\python314.dll dist\RefatAndroidBackup\python314.dll
copy C:\Python314\python314.dll dist\RefatAndroidBackup\_internal\python314.dll
```

### Tcl/Tk zipfs — blank window or Tcl errors
Python 3.14 uses `//zipfs:/` virtual paths for Tcl/Tk. PyInstaller's runtime hook cannot resolve these. Fix: extract the zips to `tcl_extracted/` as described in Step 2. The `build.spec` bundles them as `_tcl_data` / `_tk_data`.

### Inno Setup — "Bitmap image is not valid"
`WizardStyle=modern` requires 24-bit BMP at exactly 164×314 (sidebar) and 55×55 (small). JPG and PNG are not accepted. The `assets/wizard_sidebar.bmp` and `assets/wizard_small.bmp` files are pre-converted and included.

## ⚙️ Phase 1 — Environment Setup

### Windows

1. Install **MTK VCOM USB drivers** and **UsbDk**.
2. For source runs, install Python 3.14 and run `pip install -r requirements.txt`.
3. For the Windows installer, run the installed executable. MTKClient is bundled and verified on first use.
4. If the bundled client is missing or damaged, the app downloads the official MTKClient 2.1.4.1 archive to `%LOCALAPPDATA%\RefatAndroidBackup`.

### Linux (Ubuntu / Debian)

1. Open the **⚙️ Setup** tab and click **▶ Write Udev Rule**, or run manually:
   ```bash
   sudo apt install python3 python3-pip git libusb-1.0-0-dev udev
   echo 'SUBSYSTEM=="usb", ATTRS{idVendor}=="0e8d", MODE="0666"' | sudo tee /etc/udev/rules.d/80-mtk.rules
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```
2. Then click **▶ Run Setup** to install Python dependencies.

## 💾 Phase 2 — Running the Backup

1. Open **🎨 Settings** and select your device class:

   | Class | Devices | BROM Method |
   |---|---|---|
   | A | Oppo A1k/A5s, Realme C2/C11, Redmi 9A | Vol ↑ + Vol ↓ → USB |
   | B | Oppo Reno, OnePlus Nord CE MTK, Vivo V-Series | Vol ↓ only → USB |
   | C | Samsung Galaxy A10s, A12, M01s | Vol ↑ only → USB |

2. Open the **💾 Backup** tab, set destination folder, adjust skip list if needed.
3. Click **▶ Start Backup** — BROM steps for your selected class are shown in the tab.
4. Connect the phone using the displayed method.
5. Wait for `[SUCCESS] Refat Android Full Backup executed completely and verified on disc.`

After backup, verify these files exist in the output folder:

| File | Purpose |
|---|---|
| `preloader.bin` | Boot control unit |
| `boot.img` / `boot.bin` | Kernel layout |
| `nvram.bin` / `nvdata.bin` | IMEI & radio calibration |
| `system.bin` / `super.bin` | Core OS image |
| `refat_manifest.json` | Hardware profile for mismatch guard |

---

## 📄 Phase 3 — Scatter File

1. Keep device connected in BROM mode after backup.
2. Open **📄 Scatter** tab.
3. Click **▶ Print GPT Table** to verify partition layout.
4. Click **▶ Export Scatter** to write `MT6765_Android_scatter.txt`.

---

## 🔄 Phase 4 — Restore

1. Open **🔄 Restore** tab, set the backup source folder.
2. Click **🔍 Scan Folder** — confirms `.bin` count and reads the manifest.
3. Click **▶ Start Restore** and confirm the prompt.
4. Connect the phone using the BROM method for your device class.
5. The engine checks `refat_manifest.json` — if HW code mismatches, the operation is blocked:
   ```
   [CRITICAL] CRITICAL HARDWARE MISMATCH DETECTED!
   Operation BLOCKED to protect the device flash matrix from physical bricks.
   ```
6. On success, disconnect USB and hold **Power** for 10 seconds to hard-reset.
